# Alienation PC v0.1.1

A stability and diagnostics release for Windows and Linux, built on [v0.1.0](v0.1.0.md). Most of it concerns the Vulkan
renderer: GPU hangs and device losses, video memory, the pipeline cache, frame pacing, and what a crash leaves behind for
a Bug Report. It also adds controller mapping files, correct window sizing, and a faster Windows launcher.

**No game files are included.** You need your own supported Alienation PS4 package (`.pkg`); the launcher installs it.
The built-in updater installs this release without touching the game, saves or settings.

## GPU stability and Vulkan renderer hardening

- **Particle spawn loops (Issue #10).** Compute shaders that append particles in a loop are rewritten so the loop does
  a bounded amount of work however large the spawn count is, while normal particles and the final GDS counter value stay
  exactly as before. This covers `cs 0xe114750a` (CUSA00062 1.06) and structurally equivalent loops in all three builds.
  Loops that do not match the safe pattern are left untouched. This
  removes one known source of GPU hangs; it does not claim to prevent every driver reset.
- **Wave64 lowering.** Divergent branches that contain atomics, GDS append, shared-memory reads or subgroup operations
  are no longer given workgroup barriers. For the shaders this game ships the generated code is unchanged; it is a
  hardening fix.
- **Texture cache.** Eviction used the wrong minimum ages and let pinned render targets use up the whole eviction budget,
  so the cache could grow without ever evicting. Fixed, together with a thread-safety fix in the LRU cache, an early-stop
  bug in its scan, and use of stale image references after an insert. Frame images fall back instead of aborting when the
  video-memory budget is refused.
- **Sampler lifetime.** A sampler is now kept alive until the GPU has finished the last draw that used it.
- **Shader interfaces on NVIDIA.** Geometry and tessellation pipelines no longer mismatch the pixel shader's emulated
  clip-distance inputs, and pipelines without a pixel shader no longer reuse the previous draw's pixel-stage state.
- **Video.** NV12 frames with padded rows are copied correctly.
- **Persistent SUBOPTIMAL swapchain.** A swapchain the driver keeps reporting as suboptimal is replaced once instead of
  being recreated every frame, and an out-of-date swapchain is never kept.
- **GPU command self-modification.** Command buffers the game rewrites while the GPU is reading them are read in place,
  as the GPU does, for graphics, constant-engine and compute queues, including guest-address DMA that patches a compute
  dispatch. Indirect buffer ranges are validated before they are read, and the draw pipe is drained after a self-write.
  The experimental command-snapshot path was withdrawn; no snapshot copy exists in this release.

## Device lost handling, crash traces and minidumps

- A Vulkan device loss is handled in one place: the first cause is recorded once, further GPU work stops, waits end, the
  presenter stops, and the game exits with a crash report and status 25 instead of hanging on a black screen. This covers
  queue submit, sparse bind, semaphore wait and counter read, fence waits, acquire, present and wait-idle. Timelines are
  never completed on the driver's behalf.
- The GPU crash trace is much richer: it lists every pipeline and compute shader of each unfinished submission, the last
  dispatches with their group counts, the draw, present, flip and buffer-memory timelines separately, memory heap budget
  warnings and the buffer allocation fallbacks that were used.
- **Windows:** a STOP, a GPU library assertion or a device loss writes a crash report and a minidump (`alienation_NNN.dmp`)
  next to the session log. A new session log never reuses the number of a crashed session's dump.
- **Linux:** the game ends with the same status and the crash is recorded in the session log; there is no minidump.

## Low video memory and large buffers

- **Non-sparse arena fallback.** When a GPU offers no sparse buffer support, buffer arenas use ordinary device memory with
  the same migration, address-table republishing, readback and indirect-draw ordering. Sparse memory stays preferred, and
  no sparse binds are issued in the fallback. `ALN_FORCE_NON_SPARSE_ARENAS` forces it for testing.
- **Low VRAM (Issue #9).** If a device-local allocation is refused with out-of-device-memory, the buffer backing is tried
  in the other memory types the arena accepts instead of ending the game.
- **Arenas above 2 GiB.** Arenas are always two pages wide, so a GPU with a 2 GiB buffer limit (AMD) is never asked for a
  3 to 5 GiB buffer, and barriers on overlapping arenas are tracked by guest address. A timeline value the driver reports
  as "never signalled" is treated as a device loss instead of a completed tick.
- **Buffer address table.** The buffer address (BDA) table is republished after every migration, and stale bindings are
  refreshed on every draw, dispatch, copy and detile path.

## Pipeline cache and shader cache

- The cache is sealed (magic, size and checksum, 64 MiB cap), written atomically, kept per game build, and rebuilt when a
  file is truncated, empty, zero-filled, bit-flipped or from v0.1.0. Pipeline creation is retried without the driver cache.
- A BuildGate serializes pipeline builds, and game pipelines go ahead of warm-up builds.
- Driver pipeline binaries (graphics pipelines) are cached with the driver's own key.
- **Background warm-up:** pipelines from a previous run are rebuilt in the background after startup. Set
  `ALN_PIPELINE_ON_DEMAND=1` to turn it off (it takes effect where the driver supports pipeline binaries).
- Compute shaders that contain the particle loop protection are stored under a new shader revision, so a shader cached
  by v0.1.0 can never be loaded in place of the protected one. Nothing needs to be deleted: the first run after updating
  rebuilds the cache and may stutter once.

## Audio

- A backlog of audio the device has not played is dropped and refilled with silence once it exceeds the target by 100 ms,
  instead of growing, so audio no longer drifts behind the picture. Normal cadence is untouched.

## Frame pacing and Steam Deck

- Frame rate remains a presentation setting; the game still steps at its original 59.94/60 Hz.
- Repeated frames are capped at the display's refresh rate in every present mode, including VSync off and Gamescope. On a
  Steam Deck this removes presents nobody can see and the work that frame generation did on them (ALN-U3T5UQ).
- The F2 counter and the window title show the game's own frame rate, with "N presented" only when it differs
  (Issue #5, where MangoHud counted repeated presents as frames).
- The log has a one-line frame summary about once a minute, and a read-only probe records the game's fixed-step counters so
  a slow-motion report shows whether the game itself fell behind.

## Controllers

- `gamecontrollerdb.txt` beside the settings file adds SDL controller mappings; `SDL_GAMECONTROLLERCONFIG` still wins.
  Joysticks with no mapping are named once in the log with their identifiers. Xbox and PlayStation controllers are
  unaffected.
- Issue #2 (left-stick direction): a log line records the platform, the device and, when it happens, a diagonal or
  alternating left-stick pattern with raw and converted values. The stick conversion itself is unchanged.

## Launcher and windows

- **Windows launcher renderer.** The launcher now uses a hardware-accelerated Direct3D 11 renderer for a more responsive
  interface. `d3d11.dll` and `dxgi.dll` are loaded from the system folder only and kept loaded for the process, so a
  copy beside the executable is never used. If either cannot be pinned or the renderer cannot be created, the software
  renderer is used. The launcher closes before the game starts in the same process.
- **Linux launcher renderer.** SDL's normal renderer choice, with the software renderer as the fallback. There is no
  Windows-specific code on Linux.
- The log records `renderer_selected`, `frame_pacing`, `loop_sample`, `launcher_present_stall` and
  `launcher_frame_pacing_excessive` lines to diagnose launcher slowness.
- **Window fitting.** The launcher and the game window open on the right monitor, fitted to its usable area using the real
  borders and the display scale (checked at 100%, 150% and 225%). The window size is never larger than requested and the
  saved size is not rewritten. The launcher's window-size list is no longer filtered by display.

## Bug Report and crash diagnostics

- Bug Report can attach the crash dump of the same session. A dump is paired with its log only when it has the log's own
  name, sits in the same folder, was written within two minutes of the log and is a real minidump. A dump may contain
  process memory, so look at the preview before sending.
- The game build in a report comes from the selected log's own session, not from the launcher's current build.
- Online crash reports name the room state and the online callback that was running, which is how late-join crashes are
  now diagnosed.
- The lobby Worker side of the dump upload (report storage and abuse limits) is part of this release's server code.

## Known issues

- **Issue #10** (RTX 3090): the particle spawn protection is awaiting confirmation from the original reporter. Other
  causes of GPU hangs, especially on NVIDIA, may remain.
- **Issues #2, #7 and #8** remain open: #2 received diagnostics only, and no direct fix is proven for #7 and #8.
- **ALN-87B4EJ** and **ALN-S44D4A** are not resolved; ALN-CGRZLW was investigated without finding a defect.
- **Linux has no minidump.** A Linux crash is recorded in the session log only.
- **Steam Deck** has not been manually validated on hardware. Linux and Steam Deck have had much less real-hardware
  testing than Windows.
- The new Windows launcher renderer has had less real-hardware testing than the software renderer it replaces, on NVIDIA
  GPUs especially; if the launcher misbehaves, report the `renderer_selected` log line.
- **GPUs without sparse buffers:** a very long chain of arena merges can still exhaust a fallback arena.
- **Crash dumps** can contain process memory, so review the Bug Report preview before sending one.
- **True Ultrawide:** mission map markers may be shown in the wrong place.
- **Frame rates above 60** repeat the latest game frame; they do not create new game frames.
- **Local co-op** exists only on CUSA00062 1.06. Allow overlay programs is Windows only.
- Weapon drops follow the game's own level-gated data; DLC items are not available.
